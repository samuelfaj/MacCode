## Scope and delivery state

## Confirmed defects corrected locally

1. **Concurrent Git mutations and stale metadata.** `DiffPanelViewModel` previously dispatched overlapping mutations and could repaint branches/history from an older reload after a newer action. Mutation dispatch is now single-flight. Every branch/history reader applies the existing monotonically ordered request identity. Actual mutation outcome publication remains exactly once.
2. **Git loading ownership.** Reload, history and diff work shared one Boolean. An older completion could hide a newer operation's loading indicator. Each asynchronous read now finishes only its own loading token. Tests suspend two real view-model reads and release them independently.
3. **HTTP request bounds.** A header terminator arriving in a second receive could bypass the 16 KiB header limit. Excess body bytes were copied or appended before validation. The listener now checks the parsed header boundary and remaining body length before body accumulation. Socket-pair tests drive the actual parser, including exact valid body limits and trailing-byte refusal.
4. **Inline-completion process lifecycle.** The editor's real CLI transport used an undrained stderr pipe and an uncancellable blocking read, so diagnostics could deadlock completion and typing cancellation could leave processes alive. The transport now discards unused diagnostics, bounds stdout at 1 MiB, enforces a 2.5-second transport deadline, checks cancellation while polling, and owns a certified isolated process group for termination and escalation. Real executable fixtures emit more than a pipe buffer of diagnostics or ignore SIGTERM with a descendant holding stdout; they verify output and process cleanup.
5. **Live text selection.** Recent tool output reintroduced SwiftUI selection into the shared live transcript. It now reuses the existing AppKit-backed `AgentSelectablePlainText`, as does the worktree-path label. The existing selection regression remains intact.
6. **Bot permission preview.** Studio's label was fixed to Supervised, and the context-preview assembly and cache key omitted the conversation's live permission. Label, receipt and cached payload now use the selected permission. A regression switches Supervised to Full access and verifies the receipt mode, label, payload digest and cache invalidation.

## Regression-harness corrections

- Source checks now recognize the current shared empty-state component, callback-owned branching, shared schedule-card visibility, conversation-column function, VM-inclusive sidebar filter and current New menu label. Existing copy, ownership, order, accessibility and undo assertions remain.
- Release checks follow the GitHub Actions entry point and its signed release script rather than a removed GitLab pipeline. Signing, AWS role, S3 and public feed assertions remain.
- The version-93 restore fixture writes its actor lock with columns actually present in version 93, rather than invoking a current-schema mutator. Migration and restore-authority assertions remain.
- The Continue fixture advertises the permission used by its current-default thread, and waits for asynchronous provider-start failure. Durable recovery assertions remain.
- The queued-turn test waits for the actual command-log write after queue acceptance and unwraps prompts before checking them. It retains exact command counts and prompt assertions rather than crashing on an out-of-range array access.
- Docker Studio fixtures use the current execution-destination selector. Some older guest tests still assume providers or transitions no longer supported by the current contract; those failures have not been relabeled as product successes.
